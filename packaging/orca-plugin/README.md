# Stratum Orca 插件（v0.7.0）

Stratum 的 Orca 插件：面板加载**专用工作流页面**（`/plugin.html`，随包分发），与独立
WebUI 是两个产品面。分析引擎（`app/bin/stratum.exe`，MIT）随包分发，无需单独安装。

## 插件工作流（两轮优化闭环）

```
① 从盘选取 ──→ ② 参数优化 ──→ ③ 切片评估 ──→ ④ 迭代优化
   (选对象)      (预设基线→分析    (真实重切片→挂载     (第二轮建议基于真实
                  →引擎建议→写回)   →沿挤出路径应力)      应力→再写回→再切片…)
```

1. **① 从盘选取**：3D 视图选中对象（盘上仅一个时可免选）→ 页面「从盘选取」。修饰体/负
   体积忽略，多实例取第 1 个摆放。选取后自动开始第一轮参数分析。
2. **② 参数优化**：四张预设卡（安全/均衡/高速/外观，按用途措辞）选工艺基线 + 材料下拉
   （粘性，覆盖预设 PLA 默认）→ 引擎给结论（安全系数 + 风险）与 **Orca 建议**（写回内
   容清单）。
3. **③ 切片评估**：页面「切片并评估」→ 按当前盘面真实重切片（进度看主窗口）→ 挂载 →
   第二轮分析沿真实挤出路径采样应力，输出调优 G-code（可下载）与调节卡（候选/调节数/
   覆盖率/E 漂移/热区覆盖比；覆盖率 <70% 或打印域比例异常会给出「非同源件」警告）。
4. **④ 迭代优化**：写回本轮建议（对象级覆盖，要求当前选中的仍是选取时的对象）→ 回到
   ③ 重新切片评估，循环直到满意。「优化轮次」卡记录每轮 SF/覆盖率进展。

工具栏的三个按钮（从盘选取/分析盘上 G-code/写回 Orca）保留为兜底入口；页面内按钮为主。
完整调参台（参数滑杆、档位对比、批量运行、G-code 对比工具）在独立 WebUI——在浏览器打开
`port.txt` 里的地址即得完整版。

## 对话（AI 打印助手，可选）

完成一次分析后，面板出现「对话」卡：直接用自然语言驱动整个闭环（"这个件能直接打吗？""帮我
调结实一点，改完告诉我改了什么"）。v0.7 起是**带工具的 agent 循环**（模式取自 Snorca
ai-print-assistant 分支，纯插件实现、Orca 零改动）：

- **工具面（固定注册表，AI 不能越界）**：`get_print_context`（盘面对象清单）、
  `run_analysis`（对选中对象跑真实引擎分析，页面卡片同步更新）、`get_analysis`（分析事实
  块）、`read_gcode`（已挂载切片的有界摘录）、`propose_settings`（参数修改提案）。
- **提案-确认-回滚**：`propose_settings` 只做**只读比对**（读对象当前值生成 diff 卡，
  不写入）；你点「应用到对象」才写（对象级覆盖，走与写回相同的对象一致性校验），写入前存
  checkpoint，「撤销」可回滚有旧值的项（原本继承预设的键无法自动移除覆盖，会如实提示）。
- **接地与防幻觉**：最终回答只基于事实块与工具结果，白名单外数字自动移除并标注；活动行
  显示每次工具调用及其成败。上限：每次提问 ≤6 轮、≤8 次工具调用。
- **后端**：本机 codex CLI（`~/.codex` 管理模型与认证，插件零密钥）。不可用时对话卡自动隐
  藏，工作流不受影响。配置项：`CODEX_BIN`、`STRATUM_CHAT_MODEL`、`STRATUM_CHAT=0`。

## 快速安装（约 3 分钟）

1. **前置：无。** 依赖（numpy 2.5.4，cp312/win_amd64）以 wheel 随包分发（`vendor/` 目录），
   插件服务线程首次启动时自动解压进 `sys.path`——注意**不要**把 `.whl` 放到插件根目录
   （会被入口发现当成第二个入口拒绝加载）。离线/自备场景的手动安装（可选）：

   ```
   uv pip install --target "%APPDATA%\Snapmaker_Orca\python\packages\cp312" numpy
   ```

2. **放插件。** 解压 `stratum-orca-0.7.0.zip` 得到 `stratum/` 文件夹，整目录放到：

   ```
   %APPDATA%\Snapmaker_Orca\orca_plugins\stratum\
   ```

   （也可以在 Orca 的 Plugins 对话框里选择本地 zip/目录安装。）插件发现规则：插件根目录
   必须恰好一个 `.py`——`app/` 子目录不受影响，不要再多放别的 `.py`。

3. **启动 Orca**，在插件菜单里执行 Stratum（或重开一次面板）。首屏状态栏出现
   「选中盘上模型后点此送入分析」即成功。

从本仓库自行构建：`bash packaging/orca-plugin/make-plugin.sh`，产出
`dist/stratum/`（部署目录）与 `dist/stratum-orca-<版本>.zip`（分发件）。

## 面板按钮语义

页面内按钮为主入口（见上文工作流）；工具栏三按钮为兜底，语义与页面内相同：

- **⇩ 从盘选取**：把 3D 视图当前选中的对象导出为 STL 送入分析并自动开跑。未选中且
  盘上恰好一个对象时自动选那个；多选会要求只选一个。
- **⇦ 分析盘上 G-code**：对当前盘真实重切片（进度看主窗口），产出后挂载到最近一次
  「从盘选取」的会话上并自动重新分析——报告切换为沿挤出路径采样的应力调优结果。
  需先完成一次「从盘选取」。
- **⇫ 写回 Orca**：把报告 `orca_suggestions` 里的建议参数作为**对象级覆盖**写到对象上。
  写回要求**当前选中的仍是选取时的那个对象**（按对象 id 校验），换选后点写回会被拒绝
  并提示「分析对象与当前选中不一致」——重新选中原对象，或对新对象重新「从盘选取」。

## 已知限制

- 挂载的 G-code 上限 **64MB**（服务端请求体上限），超限会明确报错；缩短打印或简化模型。
- 挂载的 G-code 必须与「从盘选取」的模型**同源**（用该模型在 Orca 里切片）；面板调节卡会在
  应力覆盖率 <70% 或打印域比例异常时给出「可能不是同源件」警告。
- 一次只分析**一个对象**；多实例摆放取**第 1 个实例**的位置（分析按摆放姿态）；修饰体/
  负体积被忽略（按实体部分并集分析）。
- 写回是对象级覆盖，不改全局预设；对 STL 会话同样可写回（写到对象覆盖层）。
- 面板内「写回下载 3MF」对**多材料（多挤出槽）**文件：被触碰的槽位键会折叠为槽 0 值
  （单材料无影响）；工具栏「写回 Orca」走对象级覆盖，不受此限。

## 排查

- **端口**：服务端口由系统分配，写在插件目录 `port.txt`
  （`%APPDATA%\Snapmaker_Orca\orca_plugins\stratum\port.txt`）。可直接
  `curl http://127.0.0.1:<端口>/api/status` 验证服务活着。
- **插件日志**（诊断第一入口）：Orca 只持久化 **stderr** 到
  `%APPDATA%\Snapmaker_Orca\log\python_*.log`。启动自检探针（`[stratum-probe] ... OK`）
  全 OK 说明宿主绑定链路健康。
- **服务日志**：Stratum 自己的滚动日志在插件目录 `logs\` 下（与独立安装的日志隔离）。
- **面板卡「正在…」**：桥注册必须走 `orca.onMessage(fn)` 函数调用——面板 HTML 由插件
  生成，若改了生成代码又见到此症状，先查这里。
- **无头链路自检**：`python packaging/orca-plugin/test_chain.py`（本仓库）起独立服务跑
  sample→挂载→分析，全绿说明服务与引擎侧无问题，问题在面板/宿主侧。
